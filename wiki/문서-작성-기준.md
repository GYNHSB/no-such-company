# 문서 작성 기준

> 기록할 게 생겼을 때 **레포에 둘지, Wiki에 둘지** 정하는 기준이에요.

## 한 줄 기준

**코드가 바뀌면 같이 바뀌나요?** 그렇다면 레포, 아니라면 Wiki예요.

| 구분      | 레포 문서                                        | Wiki                                                   |
| --------- | ------------------------------------------------ | ------------------------------------------------------ |
| 무엇      | 코드와 함께 바뀌는 문서                          | 코드와 무관한 팀 기록                                  |
| 수정 방법 | 브랜치 → **PR로 리뷰** → 병합                    | **PR 없이** 바로 수정                                  |
| 예        | README, API 명세, 환경 변수, ADR, 제출 필수 파일 | 회의록, 데일리 스크럼, 회고, 결정 이유, 협업 규칙 안내 |

## 이럴 땐 어디에?

| 상황                                             | 위치                                                       |
| ------------------------------------------------ | ---------------------------------------------------------- |
| 실행 방법이 바뀌었어요                           | 레포 `README.md` (PR)                                      |
| API 요청/응답 형식을 정했어요                    | 레포 API 명세 (PR)                                         |
| 새 환경 변수가 생겼어요                          | 레포 (예: `.env.example`, `README.md`) (PR)                |
| DB나 프레임워크 같은 기술을 골랐어요             | 레포 `docs/adr/` (PR) → 아래 [ADR](#adr-기술-결정-기록)    |
| 회의에서 역할 분담, 일정 같은 팀 운영을 정했어요 | Wiki 회의록                                                |
| 오늘 데일리 스크럼 내용                          | Wiki 데일리 스크럼 페이지                                  |
| 스프린트 회고                                    | Wiki [회고](회고.md)                                       |
| AI에게 작업을 맡겼어요                           | 레포 위임 로그 (PR) → 아래 [위임 로그](#위임-로그)         |
| 협업 규칙을 바꾸고 싶어요                        | 레포 `git.md`를 먼저 수정 (PR) → [협업 규칙](협업-규칙.md) |

## ADR (기술 결정 기록)

### 언제 쓰나요?

- 기술을 **여러 후보 중 하나로 골랐을 때** (예: DB, 프레임워크, 인증 방식, 배포 방식)
- 나중에 바꾸기 어려운 결정일 때
- 역할 분담, 일정 같은 **팀 운영 결정은 ADR이 아니라 Wiki 회의록**에 남겨요.

### 어디에, 어떻게?

- 위치: 레포 `docs/adr/번호-제목.md` (예: `docs/adr/001-db-선택.md`)
- 브랜치를 만들어 PR로 올리고 리뷰를 받아요. 타입은 `docs`예요.

```markdown
# 001. DB 선택

- 날짜: 2026-11-25
- 상태: 결정됨 (제안 / 결정됨 / 폐기)

## 배경

왜 이 결정이 필요했나요?

## 결정

무엇을 골랐나요?

## 다른 후보

무엇을 검토했고, 왜 고르지 않았나요?

## 결과

이 결정으로 좋아지는 점과 감수할 점은?
```

## 위임 로그

AI에게 작업을 맡긴 기록이에요. 제출 필수 파일이라 레포에 PR로 올려요.

| 파일                        | 누가                                  | 무엇을                                                  |
| --------------------------- | ------------------------------------- | ------------------------------------------------------- |
| `docs/위임로그/본인이름.md` | 팀원 각자 (한글 이름 그대로, 1인 1개) | 내가 AI에게 맡긴 작업                                   |
| `docs/위임로그/팀.md`       | 팀 전체                               | 팀이 함께 AI에게 맡긴 작업 (예: 공통 설정, 기획서 초안) |

### 언제 쓰나요?

- AI에게 작업을 맡길 때마다 적어요. 몰아서 쓰면 기억이 안 나요.
- 늦어도 그날 작업이 끝나기 전에 적어요.

### 무엇을 쓰나요?

```markdown
## 2026-11-25 로그인 페이지 UI

- 맡긴 일: 로그인 페이지 UI 구현
- 사용한 AI: (예: Claude Code)
- 요청 내용: 프롬프트 요약
- 결과: AI가 만든 것
- 내가 고친 것: 직접 수정하거나 판단한 부분
- 관련 이슈/PR: #12
```

## 제출 필수 파일

> ⚠️ 레포는 꼭 **공개(Public)** 로 설정해요. 파일 이름과 위치가 아래와 다르면 자동 확인에서 **"없음"** 으로 표시돼요.

| 무엇           | 파일 이름 · 위치            | 비고                                           |
| -------------- | --------------------------- | ---------------------------------------------- |
| 프롬프트       | `prompts/*.md`              | v1 → v2로 바꾼 이유 포함                       |
| 기획서         | `PRD.md`                    |                                                |
| AI 작업 설명서 | `CLAUDE.md`                 |                                                |
| DB 설계        | `db.md`                     | DB를 쓴 경우만                                 |
| 협업 규칙      | `git.md`                    | 협업 규칙의 원본                               |
| 위임 로그      | `docs/위임로그/본인이름.md` | 한글 이름 그대로, 팀원마다 1개                 |
| 위임 로그 (팀) | `docs/위임로그/팀.md`       |                                                |
| README         | `README.md`                 | 실행 방법, 고른 메뉴 표, AI 사용 지도, 역할 표 |

- 모든 경로는 **레포 최상위 기준**이에요. 대소문자와 확장자(`.md`)까지 똑같이 맞춰요.
