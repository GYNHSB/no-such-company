# 위키 작성 가이드

이 위키의 원본은 레포의 `wiki/` 폴더다. 사람과 AI 에이전트가 레포만 읽어도 모든 문서를 볼 수 있게 하기 위해서다. 레포와 위키는 GitHub Actions가 서로 반영한다.

| 어디서 고치나 | 무슨 일이 일어나나                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| 레포 `wiki/`  | PR이 `main`에 병합되면 위키에 반영된다 (`.github/workflows/publish-wiki.yml`)                                      |
| 위키 화면     | 레포로 가져오는 브랜치와 이슈가 자동으로 생긴다 (`.github/workflows/import-wiki.yml`). PR을 병합해야 레포에 남는다 |

## 레포에서 고칠 때

- 문서를 고쳐 PR로 리뷰받는다. `main`에 병합되면 위키에 반영된다.
- 모든 문서는 `wiki/` 바로 아래에 두고, 하위 폴더를 만들지 않는다. 반영할 때 최상위 파일만 옮기고, GitHub 위키는 폴더 없이 페이지 이름으로만 페이지를 찾기 때문이다.
- 페이지 제목은 파일 이름에서 `-`를 공백으로 바꾼 것이다.
- 문서끼리는 `.md` 상대 링크로 연결한다. 반영할 때 위키 링크로 바뀐다.
- `wiki/README.md`는 위키의 Home 페이지가 된다.
- 새 문서를 추가하면 Home(`wiki/README.md`)과 사이드바(`wiki/_Sidebar.md`)에 링크를 추가한다. ADR은 [ADR 목록](Architecture-Decision-Records.md)의 표에만 추가한다.
- 레포에서 지우거나 이름을 바꾼 문서는 위키에서도 지워진다.

## 위키에서 고칠 때

- 위키 화면에서 페이지를 만들거나 고쳐도 된다. 그러면 바뀐 페이지를 `wiki/`에 넣은 브랜치(`docs/<이슈번호>-wiki-import`)와 이슈가 자동으로 생긴다. 이미 열린 가져오기 이슈가 있으면 그 브랜치에 더한다.
- 이슈의 "PR 만들기" 링크를 눌러 PR을 연다. 제목과 `Closes #이슈번호`가 채워져 있다. PR을 연 사람이 작성자로서 리뷰를 받고 병합한다.
- 가져오기 PR이 병합되기 전에 레포의 `wiki/`가 바뀌어 위키에 반영되면, 위키에서 고친 기존 페이지는 위키 화면에서 레포 내용으로 돌아간다. 고친 내용은 가져오기 브랜치에 남아 있으니 PR을 병합하면 다시 반영된다.
- 내용이 없는 페이지는 가져오지 않는다. 내용을 채워 저장하면 그때 가져온다.
- 가져오지 않을 페이지는 위키에서 지우고, 가져오기 브랜치에서도 그 파일을 지운다.
- 자동 가져오기가 실패했을 때는 로컬에서 `pnpm wiki:pull`을 실행하면 같은 방식으로 `wiki/`에 가져온다. 커밋과 PR은 직접 한다.
