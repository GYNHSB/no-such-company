# 아키텍처 결정 기록 (ADR)

기술 결정과 그 이유를 기록한다. 코드는 무엇을 했는지 보여 주지만, 왜 그렇게 했는지는 보여 주지 않기 때문이다.

## 작성 목적

작업이 쌓이면 예전 결정의 맥락을 잊고, 이유를 모른 채 결정을 번복하게 된다. ADR은 결정의 이유를 사람과 AI 에이전트가 함께 읽을 수 있는 문서로 남긴다.

- 결정을 바꾸기 전에 당시의 전제, 검토한 후보, 근거를 확인할 수 있게 한다.
- 전제가 실제로 깨졌는지 판단할 수 있도록 재평가 조건(Re-evaluation Triggers)을 함께 적는다.
- AI 에이전트는 세션이 바뀌면 이전 대화를 기억하지 못한다. 결정의 맥락을 대화가 아니라 문서에서 읽게 한다.

## 상태

`Proposed`는 PR 안에서만 쓴다. `main`에 머지된 ADR은 `Accepted`부터 시작한다.

| 상태       | 뜻                                          |
| ---------- | ------------------------------------------- |
| Proposed   | PR에서 검토 중이다. 팀원의 승인을 기다린다. |
| Accepted   | 승인되어 지금 적용하고 있다.                |
| Superseded | 새 ADR로 대체되었다. 대체한 ADR을 링크한다. |
| Deprecated | 대상이 없어져 더 이상 적용하지 않는다.      |

## 확신도

ADR 머리의 `Confidence` 값이다.

| 확신도 | 뜻                                                                         |
| ------ | -------------------------------------------------------------------------- |
| High   | 근거(측정, 자료, 동작 확인)를 확인했고 바뀔 가능성이 낮다.                 |
| Medium | 근거는 있지만 확인하지 못한 부분이 있다. 재평가 조건이 생기면 다시 정한다. |
| Low    | 정보가 부족할 때 내린 임시 결정이다. 바뀔 가능성이 크다.                   |

## 새 ADR 추가하기

되돌리기 어렵거나 팀 전체에 영향을 주는 결정만 ADR로 기록한다. 예: 스택을 이루는 라이브러리·도구의 추가나 교체, 폴더 구조나 모듈 경계 변경, AGENTS.md 필수 규칙 추가. 한 기능 안의 구현 방식이나 버전 업데이트처럼 그보다 작은 결정은 ADR로 남기지 않는다.

결정 단위는 라이브러리 하나가 아니라 **스택 단위**로 묶는다.

1. [ADR 템플릿](ADR-Template.md)을 복사해 `wiki/ADR-NNNN-<slug>.md`로 만든다. 번호는 기존 ADR의 가장 큰 번호에 1을 더한다. 다른 PR과 번호가 겹치면 나중에 머지하는 쪽이 번호를 올린다.
2. 결정 내용과 확신도(Confidence)는 결정한 사람이 정한다.
3. 상태를 `Proposed`로 두고, 목록 표에 한 줄을 추가해 PR을 연다.
4. 팀원이 PR을 승인하면 ADR과 목록 표의 상태를 `Accepted`로 바꾸고, 승인한 사람을 Decision makers에 추가한 뒤 머지한다. 거절되면 PR을 닫는다.

## 결정 바꾸기

`Accepted`된 ADR의 결정은 고치지 않고, 새 ADR을 써서 바꾼다. 기존 ADR에서 직접 고쳐도 되는 것은 오타, 깨진 링크, 상태, 아래의 대체 표시뿐이다.

- **결정 전체를 바꿀 때**: 기존 ADR과 목록 표의 상태를 `Superseded`로 바꾸고, 머리에 `- **Superseded by:** [ADR-NNNN](ADR-NNNN-<slug>.md)`을 추가한다.
- **스택의 일부만 바꿀 때**: 기존 ADR은 `Accepted`로 두고, 머리에 `- **Partially superseded by:** [ADR-NNNN](ADR-NNNN-<slug>.md) (바뀐 부분)`을 추가한다. 목록 표의 상태 칸에는 `Accepted (일부 대체: ADR-NNNN)`로 적는다. 예: ADR-0001에서 캐릭터 컨트롤러만 직접 구현으로 바꾸는 경우.
- 새 ADR의 Context에는 대체하는 ADR을 링크하고, 무엇이 달라져서 바꾸는지 적는다.

ADR에 적힌 패키지 버전은 결정 당시 기준이다. 현재 버전은 `package.json`을 따르며, 패키지를 업데이트해도 ADR은 고치지 않는다. 메이저 업그레이드처럼 재평가 조건에 해당하는 변경이면 새 ADR을 쓴다.
