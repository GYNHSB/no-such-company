# 리뷰 및 병합 규칙

[← 협업 규칙으로](협업-규칙.md)

## 한눈에 보기

| 항목          | 규칙                                      |
| ------------- | ----------------------------------------- |
| 리뷰어        | PR 작성자가 1명 이상 지정                 |
| 리뷰 기한     | PR이 올라오고 **24시간 안에**             |
| 병합 조건     | 승인 1명 이상 + 리뷰 코멘트 **모두 해결** |
| 병합 방식     | **Squash merge만** 사용                   |
| 병합하는 사람 | **PR 작성자**가 직접                      |
| 병합 후       | 작업 브랜치 자동 삭제, 이슈 자동 종료     |

## 리뷰어 지정 (PR 작성자)

- PR 오른쪽 `Reviewers`에서 팀원을 **1명 이상** 선택해요.
- 바뀐 부분을 잘 아는 사람을 먼저 지정해요.
- Draft PR은 아직 리뷰 요청 전이라 24시간 기한이 없어요. `Ready for review`를 누른 때부터 24시간이에요.

## 리뷰 기한 (리뷰어)

- PR이 올라오고 **24시간 안에** 리뷰를 남겨요.
- 24시간 안에 보기 어려우면 PR에 코멘트로 언제 볼 수 있는지 알려요.
- 작성자는 24시간이 지나도 리뷰가 없으면 데일리 스크럼에서 공유해요.

## 리뷰 남기는 법 (리뷰어)

1. PR에서 `Files changed` 탭을 열어요.
2. 코멘트를 남길 줄 옆의 `+`를 눌러 의견을 적어요.
3. 다 봤으면 `Review changes` 버튼을 눌러 하나를 골라요.

| 선택지            | 언제 고르나요?                               |
| ----------------- | -------------------------------------------- |
| `Comment`         | 질문이나 의견만 남길 때 (승인도 거절도 아님) |
| `Approve`         | 병합해도 좋을 때                             |
| `Request changes` | 고쳐야 병합할 수 있을 때                     |

## 승인 · 병합 절차 (PR 작성자)

1. 리뷰 코멘트마다 답을 남기거나, 수정 커밋을 **같은 브랜치에** push해요. (새 PR을 만들지 않아요.)
2. 해결된 코멘트는 `Resolve conversation`을 눌러요.
3. **승인 1명 이상**과 **모든 코멘트 해결**을 확인해요.
4. main이 그사이 바뀌었으면 최신화하고 충돌을 해결해요. ([Git 명령어 가이드](Git-명령어-가이드.md))
5. 병합 버튼 옆 `▼`에서 **`Squash and merge`**를 골라요.
6. 커밋 제목이 PR 제목과 같은지 확인해요. 끝에 PR 번호(예: `(#15)`)가 붙을 수 있는데 그대로 둬도 돼요.
7. `Confirm squash and merge`를 눌러요.
8. 이슈가 닫히고 보드가 `Done`으로 갔는지 확인해요.

### 병합 버튼이 눌리지 않아요

| 원인                     | 해결                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| 승인이 없음              | Reviewers가 지정됐는지 확인하고 리뷰를 요청해요.                   |
| 해결 안 된 코멘트가 있음 | 코멘트에 답하고 `Resolve conversation`을 눌러요.                   |
| 충돌이 있음              | [Git 명령어 가이드](Git-명령어-가이드.md)의 충돌 해결을 따라 해요. |
| Draft PR임               | `Ready for review`를 눌러요.                                       |

## 리뷰 코멘트 작성 팁

### 리뷰어

- **이유를 함께** 적어요. "이건 별로예요" 대신 "이렇게 하면 ~ 때문에 좋을 것 같아요".
- 꼭 고쳐야 하는지 알 수 있게 앞에 표시해요.

| 표시     | 뜻                               |
| -------- | -------------------------------- |
| `[필수]` | 고쳐야 병합할 수 있어요.         |
| `[제안]` | 고치면 좋지만 작성자가 판단해요. |
| `[질문]` | 궁금해서 묻는 거예요.            |

- 사람이 아니라 **코드**에 대해 말해요.
- 잘한 점도 함께 남겨요.

| 좋은 코멘트                                                                         | 아쉬운 코멘트       |
| ----------------------------------------------------------------------------------- | ------------------- |
| `[제안] 이 부분은 반복되니 함수로 빼면 다음에 고칠 때 한 곳만 바꾸면 될 것 같아요.` | `이거 이상해요.`    |
| `[질문] 비밀번호가 빈 값일 때는 어떻게 되나요?`                                     | `왜 이렇게 했어요?` |
| `[필수] API 키가 코드에 들어가 있어요. .env로 옮겨 주세요.`                         | `고쳐 주세요.`      |

### PR 작성자

- 모든 코멘트에 답해요. 고쳤으면 "수정했어요", 안 고친다면 이유를 적어요.
- 이해가 안 되는 코멘트는 바로 물어봐요.
