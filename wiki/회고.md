# 회고

> 잘한 점은 이어 가고, 아쉬운 점은 다음에 바꾸기 위해 돌아보는 시간이에요.

## 두 가지 회고

| 종류      | 언제                      | 어떻게                 | 어디에 기록                   |
| --------- | ------------------------- | ---------------------- | ----------------------------- |
| 하루 회고 | 매일 데일리 스크럼 안에서 | "막힌 점 한 줄" 말하기 | Wiki 데일리 스크럼 페이지     |
| 전체 회고 | 11/30(월)                 | KPT 방식               | Wiki `회고-2026-11-30` 페이지 |

## 하루 회고: 막힌 점 한 줄

- 데일리 스크럼에서 각자 **막힌 점을 한 줄**로 말해요. 없으면 "없음"이라고 해요.
- 예: `API 응답 형식이 정해지지 않아 화면 연결을 못 하고 있어요.`
- 풀어야 할 문제는 스크럼이 끝난 뒤 관련된 사람끼리 이야기해요.
- 이 한 줄들이 쌓여 11/30 전체 회고의 재료가 돼요.

## 전체 회고: KPT

| 항목        | 뜻               | 질문                                 |
| ----------- | ---------------- | ------------------------------------ |
| **K**eep    | 잘해서 계속할 것 | 이번에 잘된 건 뭐였나요?             |
| **P**roblem | 아쉬웠던 것      | 무엇이 우리를 힘들게 했나요?         |
| **T**ry     | 다음에 해 볼 것  | Problem을 풀려면 무엇을 바꿔 볼까요? |

### 진행 순서

1. 데일리 스크럼 페이지의 "막힌 점 한 줄"을 함께 훑어봐요.
2. 각자 Keep, Problem을 적어요.
3. 돌아가며 공유해요. 비슷한 내용은 묶어요.
4. Problem마다 Try를 하나씩 정해요.
5. 정리한 내용을 Wiki에 남겨요.

### 기록하는 법

1. Wiki에서 `New Page`를 눌러요.
2. 제목을 `회고-2026-11-30`으로 정해요.
3. 아래 템플릿을 복사해 채워요.

```markdown
# 회고 2026-11-30

- 참석자:
- 기간: 2026-11-25 ~ 2026-11-30

## Keep (계속할 것)

-

## Problem (아쉬웠던 것)

-

## Try (다음에 해 볼 것)

| Problem | Try |
| ------- | --- |
|         |     |
```

> 사람이 아니라 **일하는 방식**을 이야기해요. "누가 늦었다"보다 "리뷰 요청이 늦게 전달됐다"처럼 말해요.
