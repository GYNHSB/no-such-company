# 브랜치 및 PR 규칙

[← 협업 규칙으로](협업-규칙.md)

## 브랜치 전략: GitHub Flow

| 브랜치      | 역할                                                              |
| ----------- | ----------------------------------------------------------------- |
| `main`      | 항상 동작하는 최신 코드. 보호되어 있어 **직접 push할 수 없어요.** |
| 작업 브랜치 | 이슈마다 `main`에서 새로 만들어요. 병합되면 자동으로 삭제돼요.    |

## 브랜치 이름

형식: `타입/이슈번호-작업내용`

| 부분     | 규칙                                 | 예           |
| -------- | ------------------------------------ | ------------ |
| 타입     | 아래 타입 표 중 하나                 | `feat`       |
| 이슈번호 | 숫자만 (`#` 없이)                    | `12`         |
| 작업내용 | 영어 소문자, 단어는 `-`로 연결, 짧게 | `login-page` |

```text
feat/12-login-page
```

## 타입 표

| 타입       | 언제 쓰나요?                                                 | 브랜치 예                | PR 제목 예                                  |
| ---------- | ------------------------------------------------------------ | ------------------------ | ------------------------------------------- |
| `feat`     | 새로운 기능 추가                                             | `feat/12-login-page`     | `feat: 로그인 페이지 UI 구현 (#12)`         |
| `fix`      | 버그 및 오류 수정                                            | `fix/31-signup-error`    | `fix: 회원가입 이메일 중복 오류 수정 (#31)` |
| `docs`     | README, `docs/` 등 레포 문서 작성·수정 (Wiki는 PR 없이 수정) | `docs/5-readme-setup`    | `docs: README 실행 방법 추가 (#5)`          |
| `style`    | 코드 동작과 무관한 서식·포맷 변경                            | `style/40-format-code`   | `style: 코드 포맷 정리 (#40)`               |
| `refactor` | 기능 변화 없는 코드 구조 개선                                | `refactor/22-api-client` | `refactor: API 호출 코드 분리 (#22)`        |
| `chore`    | 빌드, 패키지, 설정 등 기타 작업                              | `chore/3-eslint-setup`   | `chore: ESLint 설정 추가 (#3)`              |
| `design`   | UI/UX 디자인 관련 작업                                       | `design/18-main-color`   | `design: 메인 화면 색상 변경 (#18)`         |

> `question`, `blocked`는 작업 종류가 아니라 **상태 라벨**이에요. 브랜치 이름이나 PR 제목에는 쓰지 않아요.
> 자세한 내용은 [라벨 및 보드 가이드](라벨-및-보드-가이드.md)를 보세요.

## PR 제목

형식: `타입: 작업 요약 (#이슈번호)`

- Squash merge를 하면 **PR 제목이 그대로 main 커밋 메시지**가 돼요. 그래서 제목이 중요해요.
- 타입은 브랜치 타입과 같게 써요.
- 작업 요약은 한국어로, "무엇을 했는지" 한 줄로 써요.

## PR 본문 (템플릿)

| 항목       | 쓰는 법                                                 |
| ---------- | ------------------------------------------------------- |
| 관련 이슈  | `Closes #12` **필수**. 병합되면 이슈가 자동으로 닫혀요. |
| 작업 내용  | 바뀐 점을 짧은 목록으로                                 |
| 스크린샷   | 화면이 바뀌었을 때만                                    |
| 체크리스트 | PR 올리기 전에 확인할 항목                              |
| 리뷰어에게 | 특히 봐줬으면 하는 부분, 궁금한 점                      |

아래를 복사해서 PR 본문에 붙여 넣으세요.

```markdown
## 관련 이슈

Closes #12

## 작업 내용

-

## 스크린샷 (화면 변경 시)

## 체크리스트

- [ ] PR 제목이 `타입: 작업 요약 (#이슈번호)` 형식이다
- [ ] `git pull origin main`으로 최신화했고 충돌이 없다
- [ ] PR 제목 타입과 같은 라벨을 붙였다
- [ ] 직접 실행해서 동작을 확인했다

## 리뷰어에게

-
```

## PR 올리기 전 확인

| 확인              | 내용                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------- |
| 이슈 1개 = PR 1개 | PR 하나에 여러 이슈를 섞지 않아요.                                                                                  |
| 최신화            | `git pull origin main`으로 최신화해요. 충돌은 **PR 작성자가** 해결해요. ([Git 명령어 가이드](Git-명령어-가이드.md)) |
| 라벨              | PR 제목 타입과 같은 라벨을 붙여요.                                                                                  |
| 리뷰어            | Reviewers에 팀원 1명 이상을 지정해요.                                                                               |
| 작업 중 공유      | 아직 완성 전이면 **Draft PR**로 올려요. 다 되면 `Ready for review`를 눌러요.                                        |

## 좋은 예 · 나쁜 예

### 브랜치 이름

| 좋은 예               | 나쁜 예                | 왜 안 되나요?                        |
| --------------------- | ---------------------- | ------------------------------------ |
| `feat/12-login-page`  | `login`                | 타입과 이슈번호가 없어요.            |
| `fix/31-signup-error` | `fix/signup-error`     | 이슈번호가 없어요.                   |
| `feat/12-login-page`  | `Feat/12_Login_Page`   | 대문자와 밑줄(`_`)을 썼어요.         |
| `feat/12-login-page`  | `feat/12-로그인페이지` | 한글은 터미널에서 입력하기 불편해요. |

### PR 제목

| 좋은 예                                     | 나쁜 예                                    | 왜 안 되나요?                 |
| ------------------------------------------- | ------------------------------------------ | ----------------------------- |
| `feat: 로그인 페이지 UI 구현 (#12)`         | `로그인`                                   | 타입과 이슈번호가 없어요.     |
| `fix: 회원가입 이메일 중복 오류 수정 (#31)` | `fix: 수정 (#31)`                          | 무엇을 고쳤는지 알 수 없어요. |
| `feat: 로그인 페이지 UI 구현 (#12)`         | `[feat] 로그인 페이지 #12`                 | 형식이 달라요.                |
| `feat: 로그인 페이지 UI 구현 (#12)`         | `feat: 로그인 UI, 회원가입 API (#12, #13)` | PR 하나에 이슈가 두 개예요.   |

### PR 본문

| 좋은 예      | 나쁜 예         | 왜 안 되나요?                           |
| ------------ | --------------- | --------------------------------------- |
| `Closes #12` | `#12 관련 작업` | 병합해도 이슈가 자동으로 닫히지 않아요. |
| `Closes #12` | `이슈 12번`     | 이슈와 연결되지 않아요.                 |
