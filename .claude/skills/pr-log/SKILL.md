# PR 올리기와 세션 기록 정리

프롬프트를 입력할 때마다 hook(`scripts/session-log.ts`)이 원재료를 로컬(`.claude/session-logs/`)에 쌓아 둬요. 이 skill은 PR을 올리는 시점에 그 원재료를 제출 파일로 옮기고 PR까지 엽니다.

## 꼭 지킬 것

- 원재료와 git 기록에 있는 사실만 적어요. 모르는 것(바꾼 이유, 사람이 고친 것 등)은 지어내지 말고 사람에게 물어요.
- 토큰, 비밀번호, 개인정보는 제출 파일에 옮기지 않아요.
- 6단계에서 사람이 확인하기 전에는 커밋, push, 이슈 생성, PR 생성을 하지 않아요.
- `main`에 직접 push하지 않아요.
- 규칙은 여기에 옮겨 적지 않았어요. 매번 원본(`git.md`, `.github/pull_request_template.md`, `docs/위임로그/팀.md`, `prompts/README.md`)을 읽고 따라요.

## 순서

### 1. 원재료 읽기

```bash
node scripts/session-log.ts pending
```

한 줄이 프롬프트 하나예요(`ts`, `session`, `branch`, `prompt`). 같은 `session`끼리 묶어서 봐요.

- 이번 PR의 작업에 해당하는 세션을 골라요. 브랜치를 만들기 전에 `main`에서 한 요청도 같은 세션이면 포함해요.
- 이번 PR과 무관해 보이는 세션이 있으면 목록을 보여 주고 "별도 기록으로 남길지, 그대로 둘지" 물어요. 별도 기록은 3단계 양식으로 같은 파일에 따로 추가해요.

### 2. 본인 파일 확인

```bash
node scripts/session-log.ts dir
```

출력된 폴더의 `owner` 파일에 본인 위임 로그 파일 이름(예: `홍길동.md`)이 있으면 그대로 써요. 없으면 `docs/위임로그/`의 개인 파일 목록을 보여 주고 어느 것이 본인 것인지 한 번만 물은 뒤, 답을 그 파일에 저장해요. 워크트리에서는 이 폴더가 지금 작업 폴더 밖에 있으니 꼭 명령으로 위치를 확인해요.

`docs/위임로그/`나 `prompts/README.md`가 없는 브랜치라면 3, 4단계를 건너뛰고 그 사실을 알려요. 이때는 7단계의 `done`도 실행하지 않아요(원재료를 남겨 둬요).

3~5단계는 초안만 만들어요. 파일은 7단계에서 고쳐요.

### 3. 위임 로그 초안

`docs/위임로그/팀.md`의 "쓰는 법" 양식을 읽고 본인 파일에 추가할 항목을 만들어요.

- 최신 기록이 위로 오게 넣어요.
- 같은 이슈의 항목이 이미 있으면 새로 만들지 말고 그 항목을 고쳐요.
- "요청 내용"은 원재료의 프롬프트를 요약해요. "사람이 고친 것"은 AI의 결과를 바로잡은 프롬프트에서 찾아요.
- 파일에 남아 있는 "작성 필요"와 "아직 뼈대예요" 안내는 지워요.

### 4. 프롬프트 이력 초안

`prompts/README.md`의 양식을 읽고 `prompts/<이슈번호>-<이름>.md`에 넣을 내용을 만들어요. 번호를 이슈번호로 쓰는 이유는 여러 PR이 동시에 올라와도 파일 이름이 겹치지 않게 하기 위해서예요.

- 원재료에서 같은 일을 다시 요청하거나 고쳐서 요청한 프롬프트를 찾아 v1, v2로 적어요.
- "바꾼 이유"는 추측을 초안으로 보여 주고 사람에게 확인받아요.
- 고쳐 쓴 프롬프트가 없으면 그렇다고 알리고, 파일을 만들지 사람에게 물어요.

### 5. 브랜치, 커밋, PR 초안

`git.md`와 `.github/pull_request_template.md`(주석 포함)를 읽고 아래를 만들어요.

- 이슈: 연결할 이슈가 없으면 이슈 제목과 본문 초안
- 브랜치 이름: 아직 `main`이면 새 브랜치 이름
- 커밋 메시지
- PR 제목과 본문: 템플릿의 모든 항목을 채워요. 의사결정 로그는 원재료에서 사람이 고른 것과 그 이유를 찾아 적어요.

### 6. 사람에게 확인받기

위임 로그 항목, 프롬프트 이력, 이슈, 브랜치 이름, 커밋 메시지, PR 제목과 본문을 한 번에 보여 주고 확인을 기다려요. 고칠 곳을 알려 주면 고쳐서 다시 보여 줘요.

### 7. 실행하기

확인을 받으면 순서대로 실행해요.

1. 이슈가 없으면 이슈 생성(타입 라벨), `main`이면 브랜치 생성
2. 확인받은 위임 로그 항목과 프롬프트 이력을 파일에 쓰기
3. `pnpm format`
4. 커밋 → `pnpm check` → push
5. `gh pr create --draft` (제목, 본문, 타입 라벨)
6. 정리한 세션 치우기

```bash
node scripts/session-log.ts done <세션ID> <세션ID>
```

### 8. 남은 "작성 필요" 알리기

```bash
grep -rn "작성 필요" docs/위임로그 prompts
```

결과가 있으면 어느 파일에 남았는지 알려요. `docs/위임로그/팀.md`와 다른 팀원의 파일은 이 skill이 채우지 않아요.
