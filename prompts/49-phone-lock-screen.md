# 휴대폰 화면 작업 규칙

- 어디에 썼나요: 휴대폰 앱 화면(#35, 하위 이슈 #49~#56)을 AI에게 맡길 때 쓰는 작업 규칙
- 쓴 사람: 김강이

## v1

```text
규칙
화면은 src/ui/screens/에 만들고, 테스트는 src/sandbox/pages/[내 이름].tsx에서 띄워 봐.
기존 kit 부품이 있으면 그걸 써. 새 공용 부품이 필요하면 만들기 전에 먼저 물어봐.
남의 폴더(src/game, src/engine, src/data/types.ts)는 고치지 말고, 필요하면 무엇이 필요한지만 알려 줘.
글은 대본 문구를 그대로 쓰고, ○○는 플레이어 이름 자리로 둬.
정답 판정, 경계심 계산은 하지 마. UI는 보여 주고 클릭을 넘기기만 해.

진행
먼저 화면별로 어떤 부품을 쓰고 무엇을 새로 만들지 짧게 계획을 보여 주고 내 확인을 기다려.
확인하면 화면 하나씩 만들고, 하나 끝날 때마다 sandbox에서 확인할 수 있게 해 줘.
커밋 전 pnpm format, push 전 pnpm check. push는 내가 승인할 때만.

기존 부품 폴더: src/ui/kit/phone/
화면 목록:잠금 화면 알림 / 문자 앱 / 은행 알림·앱 / 면접 녹화 다시 보기 / SNS /블라블라 / 원격 관리 프로그램 관리자 계정 / 신고(전화 걸기)아이폰 다크 모드 구조를 따르고, 실제 브랜드 로고·이름·색은 쓰지 마.
```

### 결과와 아쉬운 점

- 바로 쓰지 않고 AI에게 먼저 검토를 맡겼다. AI가 고쳐야 할 곳 네 가지를 짚었다.
- 이름 자리 표기가 달랐다. `○○`는 대본 문서의 표기이고, 데이터와 `types.ts`는 `{name}`을 쓴다.
- 브랜치와 이슈 규칙이 없었다. 화면 8개가 하위 이슈 8개인데, 이대로면 한 브랜치에 다 커밋할 수 있었다.
- 대본 문구를 어디에 둘지가 없었다. 화면 안에 박아 넣으면 엔진과 붙일 때 다시 써야 한다.
- "대본 그대로"와 "실제 이름 금지"가 부딪힐 때 어떻게 할지가 없었다.

## v2

```text
규칙
- 먼저 CLAUDE.md, docs/ui-kit.md, 이슈 #35와 하위 이슈 #49~#56을 읽어.
- 화면은 src/ui/screens/phone/에 만들고, 테스트는 src/sandbox/pages/gangyi.tsx에서 띄워 봐.
- 기존 kit 부품(src/ui/kit/phone/)이 있으면 그걸 써. 새 공용 부품이 필요하면 만들기 전에 먼저 물어봐.
- 남의 폴더(src/game, src/engine, src/data, src/stores)는 고치지 말고, 필요하면 무엇이 필요한지만 알려 줘.
- 화면은 내용을 props로 받아. 대본 문구는 화면 안에 적지 말고 sandbox 페이지의 견본 데이터로 둬.
- 견본 데이터는 대본(docs/261126_대본_v1-2.md) 문구를 그대로 쓰고, 이름 자리는 {name}으로 써.
- 대본 문구가 규칙(실제 브랜드·기관 이름 금지 등)과 부딪히면 멈추고 물어봐.
- 정답 판정, 경계심 계산, 증거 획득, 도착 시점은 만들지 마. UI는 보여 주고 클릭을 넘기기만 해. sandbox에서는 버튼으로 흉내 내.
- 화면 안 상태는 useState로만 써. 스토어가 필요하면 물어봐.
- 색, 글꼴, 간격은 tokens.css 변수만 쓰고, 휴대폰 화면 안의 크기는 --pt로 맞춰.
- 이미지, 영상은 새로 만들거나 내려받지 마. 없으면 임시 자리로 두고 무엇이 필요한지 알려 줘.
- 아이폰 다크 모드 구조를 따르고, 실제 브랜드 로고·이름·색은 쓰지 마.
- 패키지는 설치하지 마.

진행
- 먼저 화면별로 어떤 부품을 쓰고 무엇을 새로 만들지 짧게 계획을 보여 주고 내 확인을 기다려.
- 확인하면 화면 하나씩 만들어. 화면 하나가 이슈 하나, 브랜치 하나(feat/이슈번호-영어-설명), PR 하나야.
- 완료 기준은 그 이슈의 "할 일" 체크리스트야. 하나 끝날 때마다 ?sandbox=gangyi에서 확인할 수 있게 해 줘.
- 앞 화면이 병합된 뒤에 main에서 다음 브랜치를 따.
- 커밋 전 pnpm format, push 전 pnpm check. 커밋과 push는 내가 승인할 때만.
- PR을 올릴 때 docs/위임로그/에 기록을 남겨.

화면 목록
- #49 잠금 화면 알림
- #50 문자 앱
- #51 은행 알림·앱
- #52 면접 녹화 다시 보기
- #53 SNS
- #54 블라블라
- #55 원격 관리 프로그램 관리자 계정
- #56 신고(전화 걸기)
```

### v1에서 바꾼 이유

- 이름 자리를 데이터와 같은 `{name}`으로 맞췄다.
- 화면 하나를 이슈, 브랜치, PR 하나로 묶어 `git.md`의 규칙과 맞췄다.
- 화면이 내용을 props로 받게 해서, 나중에 엔진과 붙일 때 화면을 다시 쓰지 않게 했다.
- 대본과 규칙이 부딪히면 멈추고 묻게 했다.
- 완료 기준을 각 이슈의 체크리스트로 정하고, 엔진이 맡을 일(증거 획득, 도착 시점)과 에셋, 상태, 크기 단위 규칙을 더했다.

### 결과

- 화면별 계획을 먼저 보여 주고 확인을 받은 뒤 #49부터 만들었다.
- 진행 중에 "마음대로 push하지 말고 화면 하나마다 확인받기"를 한 번 더 일렀고, 화면을 고칠 때마다 테스트 페이지에서 확인한 뒤 커밋했다.
- 대본에 없는 통신사 이름을 정할 때 실존 이름(KT)이 규칙과 부딪혀, AI가 멈추고 물은 뒤 가상 이름으로 정했다.
