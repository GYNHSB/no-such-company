# 오버레이 워크 화면 틀

- 어디에 썼나요: 회사 노트북 앱 '오버레이 워크'의 화면 부품(`src/ui/kit/work/`) 만들기 (#27)
- 쓴 사람: 김이내

## v1

```text
test/sandbox를 최신으로 받고, 노트북 화면 틀을 만들어줘.
먼저 CLAUDE.md, docs/ui-kit.md, docs/script-guide.md, src/ui/tokens.css만 읽어. 다른 파일은 필요할 때 필요한 부분만.

목표
- 회사 노트북 앱 '오버레이 워크'의 화면 틀. 업무 메신저 구조(왼쪽 짙은 사이드바, 오른쪽 대화 영역, 아래 입력창).
- 실제 서비스의 로고, 이름, 고유 색은 쓰지 않는다. 색·글꼴·간격은 --work-* 변수만.

만들 것 (src/ui/kit/work/)
1. WorkLayout: 사이드바 + 본문. 사이드바에 워크스페이스 '오버레이', 채널(# 공지, # 업무), 다이렉트 메시지(박재훈 팀장), 메일. 선택 강조, 안 읽은 개수 뱃지.
2. WorkChannel: 상단 이름 바 + 메시지 목록(기존 WorkMessage) + 입력창. 새 메시지가 오면 맨 아래로.
3. WorkComposer: 자유 입력 대신 선택지 버튼을 보여주는 모드. 선택지는 types.ts의 Choice를 props로 받는다.
4. WorkMail: 메일 목록(보낸 사람, 제목, 시간, 안 읽음)과 본문 보기. 같은 문장으로 시작하는 불합격 메일 여러 통 위에 합격 메일 하나가 오는 장면을 보여줄 수 있게.
5. WorkButton: 주요(--work-action), 보조(테두리만).

규칙
- 표시만 한다. 메시지 도착, 경계심, 판정 로직은 넣지 않고 props와 콜백으로 받는다.
- 버튼 id는 docs/script-guide.md의 규칙(btn_화면_동작)을 따른다.
- 부모 크기에 맞춰 늘어나게(고정 px 너비 금지). 버튼은 button 요소, 포커스 표시.
- 확인용 src/ui/kit/work/WorkPreview.tsx: src/data/days/day1.ts의 메시지로 조립한 미리보기.
- 끝나면 pnpm check. 오류는 이번에 만든 파일 안에서만 고친다.
- docs/ui-kit.md에 새 부품 설명을 같은 형식으로 추가.
- 커밋 "design: 오버레이 워크 화면 틀". push 전에 나한테 확인받아.

애매하면 만들기 전에 먼저 물어봐.
```

### 결과와 아쉬운 점

- AI가 시작 전에 멈추고 물었다. 작업 브랜치가 `test/sandbox`로 되어 있었는데, 팀은 이미 `main`에서 작업하기로 한 뒤였다.
- `docs/script-guide.md`는 레포 어디에도 없어서 버튼 id 규칙을 확인할 수 없었다.
- 미리보기를 `day1.ts`로 만들면 다른 사람이 작업 중인 `src/data`에 기대게 된다.

### v1에서 바꾼 이유

- `main`에서 작업하기로 해서 `test/sandbox`를 `main`으로 바꿨다.
- `docs/script-guide.md`가 없어서, 없는 파일은 시작 전에 알리게 했다.
- `src/data`는 다른 사람이 작업 중이라 고치지 못하게 하고, 미리보기 데이터를 `day1.ts` 대신 파일 안 예시로 바꿨다.

- 없는 파일(`docs/script-guide.md`)을 알리며 한 번 멈춘 뒤, 요청문의 `btn_화면_동작` 규칙으로 진행했다.
